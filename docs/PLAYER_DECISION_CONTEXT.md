# Player decision context, v1.32

## Player value

The September 9 benchmark discussion prioritizes a player's own situation, meaningful alternatives and a check after play. This increment removes two entrance obstacles and adds context to two existing decisions. It does not establish repeat use or product-market fit.

## Entrance

- Dota: entering a public Match ID is the primary action; the worked professional example stays optional. Loading requires a deliberate form submission and retains the existing provider boundary.
- GTA: the worked example uses the existing complete-run session allocator. It has one ready-stock sale and an available repeatable activity, explicitly hypothetical receipts and observed-duration assumptions. The full tool receives exactly the displayed assumptions.
- All six game choices and return-to-saved-plan behavior remain available. Supporting homepage analysis follows the selected game.

## Dota episode

Use the existing three-minute replay focus, or the whole critical phase when continuous data is insufficient. Join it with the existing sanitized and version-gated draft purchase review. A fixed three-minute lookback supplies separate earlier-purchase context; never include later purchases.

Both teams receive the same presentation limits. Named mechanic checks can explain what to inspect, but cannot establish that an ability was ready, an item was delivered or a combination occurred. Missing purchase logs remain missing observations. Final inventory cannot manufacture a time. A match without a defensible economic window does not receive an invented one.

## WoW existing stock

In absolute-sales mode, the player confirms remaining units of the same item and quality. Allocate the entered conditional sales count to that stock first. Only the residual count is available to the newly crafted batch. Round the new batch to complete crafts and respect the existing protected cash reserve separately.

Do not infer cost basis or proceeds for old stock. Cash, inventory-at-material-cost, profit and recorded outcomes continue to describe the new batch. Old saved scenarios and journal records default to zero existing stock. Reusing an outcome requires confirmation of current stock and current wallet; historical isolated sales are not total future market capacity.
